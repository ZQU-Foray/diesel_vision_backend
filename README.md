# diesel_vision_backend

## 2026-11-22 向下抓取

新增顶抓路线：准备到安全高度后，保持工具朝下，TCP先定高水平对准目标，再固定x/y竖直下降。
两段均使用笛卡尔直线规划，逐段检查限位、奇异与简化碰撞；失败不改走斜线。不代表真实夹爪抓取成功。

## 2026-11-21 末段TCP直线需求

RoutePlan可显式要求最后一段保持TCP朝向与直线路径；此前各段均为关节插值，不能保证直线。
新增plan_cartesian：从实测/前段终点出发沿线求连续IK、检查J/限位/碰撞、按J与曲率导出关节速度和加速度，
同步限制关节/电机/TCP速度加速度，再做五次时间缩放。无法保持朝向、连续解或任何约束失败即拒绝，不降级成弯线。
仿真记录计划和实际TCP对末段直线的最大偏差；默认detour使用直线末段，保留关节版本供回归对照。

## 2026-11-21 第二步：经过点绕行与相机输入

新增RoutePlan组合多段JointTrajectory：先直接路径，失败后尝试外部明确给出的缩回/抬高经过点序列，
逐段复用相同IK/路径检查；任何段失败就淘汰整条候选，不强行跨越。只有全部段可行才供仿真执行，段间持续到位后切换。
这是有限候选搜索，不等于完整RRT或一定能找到路线。仿真增加detour场景证明直接路径失败而绕行成功；block场景仍应拒绝。
仿真相机观测由前端彩色标记板PnP产生，经arm/observation转换后作为目标；不得读取目标真值冒充识别。

## 机械臂点到点仿真链路（2026-11-21，需求与边界）

新增arm/motion_pipeline：基座系期望TCP完整位姿、固定安装座到TCP变换、当前关节反馈
→解析IK候选（只接受本机构可实现的水平朝向）→关节直线路径→沿途FK、几何/电机限位、位置J奇异值、外部碰撞检查
→候选运动量排序→五次时间缩放轨迹（关节与电机速度/加速度均限制）→带时间/故障/到位检查的反馈监测。
所有参数显式注入；碰撞检查未提供/未知即拒绝，不输出可执行轨迹；不自动绕障、不实现TCP直线接近。
路径采用有限采样，分辨率有上限保护，不声称连续碰撞证明。TCP偏置、角度映射、障碍模型必须与实际模型一致。
仅允许静止起点；反馈含速度，不允许假定运动中的机械臂已经停止。连续角不自动wrap执行。
提供src/arm/motion_sim_bridge.cpp文本进程接口，供工作区MuJoCo演示调用正式C++计算，仿真不另写IK。
演示限位、单位传动、无重力质量/增益、胶囊杆与球形障碍/地面均为合成参数；无真实串口、使能或抓取。
真实碰撞模型、自碰撞/底座/工具完整外形、标定、动态障碍与硬件停止策略尚未验收；仿真成功不能授权实物。

## src按业务分区（2026-11-14）

```text
src/
├── armor/   装甲板自瞄：融合、EKF、关联、锁定/预测、直瞄与云台控制适配
└── arm/     机械臂：正运动学、位姿时间检查与坐标转换
```

当前fusion/WorldSnapshot实现仍有装甲板ID/单车跟踪假设，因此归armor，不冒充通用机械臂融合；公共include已同步按业务分区。

## 机械臂后端预研（2026-11-14）

新增 `arm/level_arm.hpp`：底座yaw、大小臂各149mm、末端理想保持水平的三自由度正运动学。参数来源为本人实物说明，轴心距和轴偏置待复核，几何角不等于电机编码器角。新增 `arm/observation.hpp`：消费相机系完整位姿、同采样时刻的基座到相机变换，检查时间/坐标系/旋转后计算基座系目标。后端仍不引入OpenCV/推理运行时。

不迁入旧四轴教学任务仿真，不冒充实物闭环；逆解、限位、轨迹、碰撞、真实相机/电控/夹爪反馈后续实现。接口为待评审本地C++草案，PR目标dev。

### 机械臂角度映射草案（2026-11-20）

按本人要求预留 `arm/motor_angle_mapping.hpp`，离线完成电机角与LevelArmAngles双向转换，全部rad。
使用显式注入的仿射关系：几何角 = 映射矩阵 × (电机角 − 电机零位) + 几何参考角。
矩阵可表达方向、传动比和线性耦合，不能假定每个电机只影响一个几何角；非线性传动不在本草案范围。
默认未配置，转换返回空；只有调用者提供有限、可逆的参数才可计算。数学参数有效不代表实物已标定。
模块不做角度wrap，不读取设备，不自动发送，不处理限位/时效/碰撞；反馈应先解码单位与累计圈数。
未来目标路径需先筛选几何角、转成电机目标再检查电机域限制；反馈转换后用于监测，不以超限后的回报代替发送前检查。

### 机械臂目标静态限位检查（2026-11-20）

`arm/target_angle_check.hpp`提供纯计算检查：显式配置几何角与电机角的上下界(rad)，
依次检查配置/输入、几何角范围、角度映射、电机角范围；返回明确失败原因和轴下标，失败不输出电机目标。
越界拒绝，不静默截断。边界包含在范围内，安全余量由调用者预先放入配置；没有实物默认限位。
这只筛选一个目标状态，不检查当前反馈、时间戳、轨迹、中间碰撞、近奇异、速度与到位，绝不构成运动授权。

### 第一版机械臂闭环全景（2026-11-20）

参考[MoveIt Humble运动规划分层](https://moveit.picknik.ai/humble/doc/concepts/motion_planning.html)的状态/目标约束、规划、执行分离，不表示已移植MoveIt或安装完整框架。

| 环节 | 本项目落点 | 当前状态 |
|---|---|---|
| 看见目标、估计相机系位姿 | 前端arm | 尚未验收实际机械臂目标检测/位姿链 |
| 目标转基座系 | 后端arm/observation | 已有带时间与SE(3)检查的纯计算接口，真实外参未验收 |
| 知道当前手在哪里 | 后端arm/level_arm + motor_angle_mapping | FK和映射已有离线测试，真实映射参数未提供 |
| 求目标摆法并筛选 | 后端arm：未来IK + target_angle_check | 静态几何/电机域限位已实现；IK、连续选解与碰撞待做 |
| 安排怎么走与何时到 | 后端规划模块/后续明确的装配入口 | 轨迹、速度加速度约束尚未实现 |
| 发送与接收 | 平台通讯 + 装配根 | 机械臂协议与电控待确认，不复用云台字段假装完成 |
| 确认执行结果 | 后端监测/后续任务流程 | 反馈时效、故障、持续低速到位、抓取验证待做 |

第一版先以手动基座系目标替代视觉：目标→逆解→约束筛选→轨迹→仿真反馈→到位/失败。
JD所需系统联调与故障定位由这条闭环逐项产出日志/测试；ROS2节点、TF和录制回放按集成阶段补，不把当前库构建当ROS2系统开发经历。仿真与实物指标分开；没有腕轴/夹持反馈不宣称任意姿态装配或抓取成功。

> **L4** · owner 角色：视觉

视觉后端：装甲板自瞄的融合、跟踪与瞄准解算，以及机械臂几何与处理模块；不是机械臂专用仓库。

消费前端逐帧 `Observation` 与队友共享目标，**不关心来源**。跟踪环是硬实时。
检测识别、PnP 与相机调试归 `diesel_vision_frontend`，本仓不链接 OpenCV / ONNX Runtime。

## 接口

### 统一C++后端接口

`AimPipeline` 是装甲板自瞄业务的统一入口；机械臂模块使用独立接口。它接收前端逐帧 `Observation`（相机系位置、板法向、局部板号、重投影误差），
在本仓完成手眼与姿态变换、时间门限、Tracker/EKF、锁定选板、预测和直瞄。
它不打开相机、不运行检测、不链接 OpenCV 或推理运行时，也不实现弹道与发射；弹道接口仍是 `world_aim_solver.hpp`。

`NativeControlLoop` 独占 USB，负责握手、心跳、时效检查、角度限速和控制撤销；启动默认只观察，
显式 arm 后才发送。当前仍按主机取帧/姿态接收时刻配对，不伪称曝光—IMU 硬件同步，也不保证硬实时验收。

| 产出 | 内容 |
|---|---|
| 云台指令 | pitch/yaw（硬实时环，100–1000 Hz） |
| 目标状态 | `AimPipelineResult.snapshot`：`WorldSnapshotData`（0/1 条 `SnapshotTrack`，带世界系位置/速度与置信度） |
| 融合计数 | `fused_count` / `fused_dropped` / `fused_merged`，供离线诊断「这帧为什么没目标」 |

当前 `aim_at()` 输出的是云台系相对指向角。RoboLink v0.2 的控制快照要求世界系目标角，因此协议适配函数必须收到有效的云台系到世界系四元数，先旋转指向向量再解出世界系 yaw/pitch（rad）；无有效姿态时拒绝组帧。时间对齐尚未实现，真实控制仍禁用。握手或状态回读前也拒绝排队；排队不证明电控接受或执行。

### 相机调试入口已迁出

海康相机取流、双模型检测、PnP 与静止相机诊断窗口归 `diesel_vision_frontend`；
本仓不再提供 `foray_auto_aim_live_debug` / `foray_world_tracker_worker` 等工具。
后端离线调试请用单元测试或由装配层喂入 `Observation` 回放。

当前离线 `Tracker` 负责单目标的连续确认、四板位置与朝向联合关联、短暂丢帧与超时重置。其输入位置和装甲板朝向必须已转到同一个稳定坐标系，并使用图像采样时间；它不负责相机/IMU 时间对齐、敌我识别或真实云台控制。仅 `Tracking` 状态可作为后续瞄准的候选，`Detecting`/`TempLost` 不表示已安全锁定。距离/朝向门限、半径和逐维初值方差由调用者注入，实机使用前必须标定和调参。

旋转目标的离线回归测试已覆盖“板绕中心运动不能被当作车体平移”：Tracker 将板位置和朝向联合送入整车 EKF，角度新息按 ±π 折返，朝向观测方差可配置。测试通过只说明合成观测下的估计行为；真实模型角点误差、同帧重复候选、误认板、半径/高度差及实机时序仍需分别验证。

`TrackerResult.diagnostics` 仅供离线诊断，区分空输入、ID、朝向、距离和时间间隔等拒绝原因；不会放宽门限，也不代表目标可安全控制。模拟器同板对照已发现模型四角相对物理外角内缩，需先校正输入契约再标定实车门限。

离线 v1 另提供 `aim_at_tracked_armor()`：用 Tracker 的整车状态、局部板号与显式预测时长计算未来板位置，再按下发时刻云台姿态转成直瞄角。它不做图像/IMU 对时、目标可见性判定、弹道或发射授权；当前仅供模拟器适配层使用，不能直接接真实电机。

### 融合层（I7）

`fuse_observations(observations, now_s, FusionConfig)` 在任何几何变换之前运行，规则按优先级固定：

1. **时间**：`stamp_s` 非有限、晚于 `now`、或早于 `now - max_age_s`（默认 100 ms）→ 丢弃；
2. **类别**：3v3 只实装装甲板，`armor_only` 时非 `TargetClass::Armor` 一律丢弃；
3. **几何**：板号必须在 0..2、位置有限且 `z > 0`、`normal_valid` 时法向必须有限；
4. **去重**：同板号且距离 < `same_armor_merge_m`（默认 0.15 m）判为同一块板，
   **自车相机优先**，同来源取置信度高者；不平均位置——平均会把两车标定误差混进来。

`build_world_snapshot(TrackerResult, stamp, max_missed_frames)` 把单目标跟踪结果转成快照轨迹：
`Lost` 不产生轨迹（`valid=false`），`Detecting` 上限 0.5，`Tracking` 由丢帧数衰减，`TempLost` 固定 0.2。
**预测帧永远不会伪装成已确认锁定**。

> 当前 Tracker 是单目标跟踪器，因此快照至多 1 条轨迹；多目标快照要等每目标一条轨迹后才有意义，
> 届时扩展 `build_world_snapshot` 的内部，消费方契约不变。

**目标源可插拔**（本仓只消费融合后的目标）：

| 来源 | 特性 |
|---|---|
| 自身相机（装甲板识别） | 高精度、低延迟、视野受限 |
| 哨兵共享态势 | 覆盖广、精度低、有延迟 |
| 队友共享 | 同上，来源可能重复 |
| 裁判系统 | 无位置，仅血量/状态 |

## 两条硬约束



### 1. 必须**过滤**友军，不只是标记友军



步兵开火由操作手授权（见 `foray_docs/algorithm_structure.md` §5），因此

**禁止把友军作为瞄准目标**。这是**过滤**——友军不得进入候选目标集，

而不是标记为「友军」后交给下游判断。



### 2. 跟踪环仍是硬实时



人在环允许端到端数百毫秒延迟，**但这不放松跟踪环**。

云台伺服仍在硬实时域（1–10 ms）：去中间件、直连 HAL、独立实时线程、禁止动态分配与锁。



## 注意



- 开火门限的作用点是本仓的**目标准入**——归属 X1 安全门，不归本仓自决

- 哨兵/步兵/英雄共用本仓代码，差异只在装配根与参数
